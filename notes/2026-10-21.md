# 2026-10-21

## What I built

`garden` - a daily engineering rhythm that turns my burst-style work into a
steady, visible record.

The problem was never that I did not build real things. It was that I built
them in one day and then went quiet for three weeks, and that I committed a
whole day's work as one giant commit. GitHub's contribution calendar counts
*commits per day*, so a week of serious work could look like a single faint
square.

## What I learned

- **The calendar counts commits, not lines.** That single fact explains the
  whole problem. `fix: stuff` with 40 files is one contribution. The same work
  in four logical commits is four.
- **Classification beats a fixed convention.** Splitting a batch by path
  pattern first (tests, docs, deps, CI) and by diff content second produced
  commit messages that were actually readable, without me writing them.
- **A bot has to author as a human.** A commit authored by a bot identity is
  not attributed to my account, so it never shows up. The commit author email
  has to be a verified address on the account.
- **Budgets keep automation honest.** Running every check every day produced
  fifteen commits and an unreadable history. Capping the day's commits and
  running the checks lazily fixed both.
